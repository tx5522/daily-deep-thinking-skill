# 证据、进步评估与隐私

## 1. 证据最低要求

讨论中的事实强度不能超过材料支持的范围。引用之前阅读与论点有关的原文，不把搜索摘要当全文；优先原始研究、官方数据及作者原作，必要时用可靠综述解释研究分歧。

一条关键证据至少交代：

- 来源：作者或机构、标题、年份、可访问出处；书籍补版本和实际可核验位置。
- 内容：研究对象或适用人群、比较了什么、观察到什么；重要数字的口径和时间。
- 边界：相关还是因果，样本和设计限制，不能据此推出什么。
- 作用：它支持或削弱当前哪条机制，有什么竞争解释。

时效性事实先联网核验。政治、医疗、法律、金融等高风险事实尤其不能凭记忆给确定结论。无检索工具时说明限制，改用明确的假设推演，不假装已核验。

有可靠分歧时呈现主要证据与其强弱；不是每个观点都配一份相同权重。优先寻找可能改变当前判断的材料，而非只搜证明 AI 正确的材料。

## 2. 原文、作者观点与构造案例

【作者原文】只能使用实际读取并可追溯的短引文，遵守平台引用限制；译文标“译文”，AI 转述不使用引号。没有页码就给真实可定位的章节、段落或网页位置，不能补造页码。

【作者观点】与【AI 推论】分开。解释作者为何这样主张、支持条件、可能反例；不要求用户接受权威。每次有相关且可取得的原文时，安排一段精读；没有合适原文时使用可核验研究，不为完成指标硬塞名人名言。

【AI 构造案例】中的数据只对案例成立。它可以演示逻辑，但不能证明现实中的效应大小、发生频率或因果关系。纯计算结论需给出假设；计算无误不等于现实假设成立。

检索失败或材料不可读时，标记 `evidence_status: unavailable` 或 `partial`，说明哪一步仍待检验。不得用一个构造反例替代所声称的实证验证。

## 3. 评估的是行为，不是人格和立场

以下只是本项目的观察尺度，不是标准化心理测验。只评本次目标涉及的维度，不给用户智力、人格或“理性程度”贴标签；不输出伪精确的总分、百分位或能力排名。

| 维度 | 可观察行为 | 不足以证明掌握 |
| --- | --- | --- |
| 机制解释 | 自己说明因果环节、假设和限制 | 重复“供需”“博弈”等术语 |
| 证据判断 | 比较口径、样本、对照及替代解释 | 只列来源或信任名气 |
| 边界识别 | 说明哪个条件变化会推翻或收窄结论 | 泛泛说“不能一概而论” |
| 观点修正 | 解释为何改或不改、哪些部分仍未知 |
| 迁移应用 | 在新情境使用同一原理并检验适用性 | 背出上一个案例的答案 |

每项状态只从以下选择：`未观察`、`提示后完成`、`独立完成`、`跨场景复现`。它们是具体记录标签，不把多个维度相加成综合评分。

每次写一条有依据的观察，例如“在对方降价的新条件下，用户主动补出了销量和利润率的区别”。不能只写“思维更深刻了”。引文必须有真实回应；否则写转述。区分事实错误、推理错误、知识缺口和价值偏好，不能把不同偏好判成能力不足。

政治讨论同样只检查事实与推理是否匹配，不评价用户立场，不对政治人物、政党或选项作评分、排名或投票建议。

## 4. 基线、复盘与迁移

第 1 次可建立基线：用户未经教学的判断与理由。第 5、10、15、20、25、30 次用新场景复盘。只在目标能力、难度和提示程度大致可比时讨论变化，并写明局限。

过程包含帮助时，不能把帮助后的正确答案当独立能力。单次进步不足以证明稳定迁移；后续出现相同表现才标“跨场景复现”。没有可靠早期记录时，不能追溯编造基线。

完成标准流程可标 `completed`，但能力表现仍可能是“提示后完成”，证据也可能有缺口。课程完成数量与能力状态分别记录。

## 5. 存储、授权与公开发布

公开仓库只放规则、空白模板和明确标注的构造案例。不提交真实对话、个人财务信息、心理画像、联系方式、登录信息或私有来源内容。

经用户授权才向私有路径保存实际记录。保存失败或没有写工具时，明确说“本次记录仅在当前聊天中”，给可复制文本，不承诺跨设备或跨会话自动恢复。

项目的 `.gitignore` 只是防止误提交的一层措施，不会撤回已被跟踪或已发布的内容。公开提交前仍需人工检查差异，不能把忽略规则当保密系统。

升级只修改通用方法与模板，不将历史私人讨论搬入公开仓库。任何“已保存”“已同步”“已验证”都必须有实际操作结果支撑。
